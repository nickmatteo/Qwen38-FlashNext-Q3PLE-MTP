# Q3_PLE + MTP at 61,440 retained tokens

## Verdict

`MEASURED` - the independently rechecked nine-process benchmark retained
61,440 actual tokens, processed 87 new query tokens, and returned 512 tokens per
request. Corrected native MTP plus paired IQ CPU kernels reached **20.253 tok/s**
by the pinned server's committed-decode convention. The 25 tok/s target was not
reached, and this experimental runtime was not promoted as the daily profile.

This is the strongest qualified occupied-context result in the project. It is
separate from the 31.45 tok/s short-prompt result and the native-vision daily
route.

## Repeated comparison

Each condition used three independent processes. Every process ran one prime
request followed by two warm measurements. The order was counterbalanced:
target/MTP/pair, pair/MTP/target, then target/MTP/pair.

All 27 requests restored the same 61,440-token state, reported
`cache_n=61440` and `prompt_n=87`, and returned the same exact 512-token vector.
Context allocation was 65,536. Context shifting, truncation, and compaction were
disabled.

| Mode | Median process decode | Lowest warm block | Highest warm block | Median warm wall time |
| --- | ---: | ---: | ---: | ---: |
| Target-only | 19.276 tok/s | 18.926 | 19.483 | 28.64 s |
| Corrected MTP | 19.649 tok/s | 19.188 | 20.134 | 28.30 s |
| Corrected MTP + paired IQ CPU | **20.253 tok/s** | 19.834 | 20.902 | **27.40 s** |

Every warm MTP/pair request proposed 257 tokens and accepted 235. Drafted and
rejected tokens are excluded from committed output throughput. Each response
returned all 512 tokens; the server times 511 generated steps because the first
token is accounted with prompt processing.

## Why this matters

The 31.45 tok/s headline uses a 232-token prompt in a 16K allocation. This
benchmark measures decode while a genuine 61,440-token prefix remains present.
The target uses AtomicChat's AD-4.27bpw neural quant with only the 51.2B-element
PLE table replaced by the project's Q3_PLE format. It therefore preserves a
much stronger neural-weight quantization than the very-low-bit 12 GB demos
typically used to make this model fit.

The paired CPU result is also correctness-gated. Earlier faster-looking MTP
rows were rejected when exact output changed. Here, all qualified outputs share
the same token SHA-256.

## Resource envelope

Across the primary 27-request matrix:

- minimum free VRAM: 1,067 MiB;
- minimum available system RAM: 12,862,615,552 bytes;
- maximum owned process RSS: 37,484,175,360 bytes;
- sampled system swap growth: zero.

The system used one RTX 5070 12 GB, 64 GB DDR4-3000, a Ryzen 9 5900XT, and an
NVMe SSD. GPU and CPU memory are separate; this is not a unified-memory system.

## Exact runtime boundary

The corrected repeated-test runtime is based on source revision
`c9d0b6139b2a312af70c25e1b05974ee3ddcf1ce`. The paired IQ CPU foundation is
`30ecc957897a35136c3b530cd0ac394eaa38433a`.

The exact 24-commit delta from the previously published `73b803` source is in
`patches/llama.cpp/73b803-to-c9d0-occupied60k/`. The sanitized measured profile
is `profiles/q3ple_occupied_61440_pair.json`. This row used its 1,487,721,536-byte
shared-tensor sidecar (SHA-256 `E71A1131...531F1C29`), not the daily route's
2,202,883,264-byte promoted sidecar.

The gathered sparse-attention repair serializes each verification token's
gathered-attention invocation for two-to-four-token all-output verification.
It restored exact output through 61,440 retained tokens. This is a narrow
correctness repair, not a claim of universal model correctness.

The compact machine-readable audit is published at
`results/DSH-MTP-FUTURE-002/qualification-independent-recheck.json`.

## Limits

- Six warm blocks per condition are clustered within three processes; they are
  not six independent process replicates.
- Restore avoids recomputing the old prefix. It does not remove the retained
  history or make an arbitrary cold transcript instantly available.
- The fixture is one source-excerpt coding continuation. It does not establish
  broad coding, reasoning, or multimodal quality.
- A later single-process candidate reached 20.518 and 20.797 tok/s, but it lacks
  the matched three-process A/B required for promotion.
- The 25 to 30 tok/s occupied-context goal remains open.
